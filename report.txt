REPORT: origin of the CEEX vs PHOKHARA pion-angle discrepancy
KLOE-LA (Strong2020 KLOE-I), e+e- -> pi+pi-gamma, fixed-order NLO, F(pi)=1, no VP
23 Sep 2026 -- repository github.com/jpaltrinieri/CEEX_PHOKHARA_ANALYSIS
==========================================================================================

1. SUMMARY
----------
The disagreement is caused by two errors in PHOKHARA 10.0, both in the 1-photon ISR x FSR
interference at NLO (routine ampLO, pion branch, used only with nlo2=1, i.e. full NLO):

  H1  phokhara_10.0.f:9969-9982. The vertex-correction factor (ver_f+ver_s) is written inside
      dreal(...) after the last of the four helicity products, so it multiplies only that
      term; the other three terms of the tree interference Re[I*F] are added a second time
      with coefficient 1 instead of O(alpha). The muon analogue (10384-10394) is correct.

  H2  phokhara_10.0.f:9998-10007 with hard_soft_part/ISRcurrent_no_mass_terms.f:134,210
      (block "B5" = Re[F* (apl-ami)], ISR one-loop current x FSR tree). Its coefficient
      V1(1) = (1 - 2 alpha/4pi V1)/Sp keeps (a) the tree "1" and (b) the analytic ISR soft
      function 2 ln(4w^2)(ln m^2+1)+..., so B5 carries an extra Re[F*I](1 + soft_ISR(w)).
      The tree interference is already added in the fsr=2 block, and in the nlo2 mode the
      analytic ISR soft function is replaced by the eikonal in NLOpions (it is subtracted in
      ver_s, vertLO and the leptonic tensor, but not here). Part (b) is w-dependent: it is
      why PHOKHARA's asymmetry depends on the soft-photon cutoff.

Both are C-odd, so they cancel in sigma over the symmetric KLOE-LA cuts and show up only in
the pion polar angles (theta+, theta-, theta_avg) -- exactly the observed pattern.
With both removed (phokhara_fix = variants/h1.patch + variants/h3.patch) PHOKHARA agrees with
CEEX-main and with BabaYaga, and its result no longer depends on w (section 5).

      D - pred(H1+H2)     rms 0.000025, mean 1e-6

4. THE FIX
----------
RUN/RUN_PHOKHARA/variants/ (built with variants/build.sh, production binaries untouched):
  h1.patch   ampLO pion ISRxFSR block:  ...*cvac_s *(ver_f+ver_s) )  ->  ...*cvac_s )*(ver_f+ver_s)
             i.e. Re[T1+T2+T3+T4]*(ver_f+ver_s), as in the muon code (the pion comment
             "factor 2 of this interference taken into account in ver_f and ver_s" agrees:
             ver_f, ver_s are |M|^2-level corrections).
  h3.patch   after B5: subtract Re[F*I](1+softisr), with softisr the same analytic ISR soft
             function nlo2 subtracts from ver_s:
             softisr = alpha/pi*(-ln(4w^2)(1+ln(me^2/s)) - ln^2(me^2/s)/2 - ln(me^2/s) - pi^2/3)
  phokhara_fix = phokhara_nostop + h1.patch + h3.patch
  (h2.patch is the T2 diagnostic probe, not a fix.)

6. CAVEATS AND OPEN POINTS
--------------------------
- Only the configuration studied here was tested: F(pi)=1, no VP, KLOE-LA cuts. The errors are
  in code paths that are active for pion=1 with nlo2=1 in any configuration (they do not
  depend on FF_pion or ivac), so they should also affect the Strong2020-FF KLOE results
  (there the NLO gap in A was 0.012, CEEX 0.0804 vs PHOKHARA 0.0924). Not re-run with FF.
- Muons (pion=0) take a different branch (ampLOm2, correct) and are not affected.
- Totals and C-even distributions are unaffected by both errors (verified: sigma unchanged,
  C-even per-point agreement 1e-5).
- The small CEEX - BabaYaga offset in A(th+) (+0.00027, ~2 sigma at each Emin) is 150x smaller
  than the PHOKHARA effect and is left open.
- Tests T5 (charge-class split) and T6 (2-photon point by point) of plan.txt were not needed:
  the 2-photon part agrees (T3) and H1+H2 explain the 1-photon part at 2.5e-5 per point (T4).

7. OTHER FINDINGS ALONG THE WAY
-------------------------------
- PHOKHARA_10.0 as checked out has an empty stub variables_cuts.f (no cuts, no histograms);
  the KLOE-I cuts come from monte-carlo-results-root-scenarios. The card format and FF_pion
  numbering changed w.r.t. the Strong2020 cards (seed and GVMD lines; FF_pion=-1 is F=1).
- PHOKHARA stops ("Warning! Max(i) too small!", phokhara_10.0.f:1910,2135,2263) when a weight
  exceeds the scanned maximum and writes no histograms; dropping such seeds (as the Strong2020
  merge did) biases the result. For weighted events the stop is unnecessary (phokhara_nostop).
- PHOKHARA's virt_pions overwrites its quad-precision momentum arguments (by ~1 GeV); harmless
  in production, but any second call in the same event gets wrong momenta.
- In the 5-Aug reference folder, Phokhara/NLOnovp_*.csv is the MUON result (0.9925 nb).
- CEEX: diverging rank outputs occur at the few-per-cent level at 100k (11/300); they are
  excluded before merging (check_total.sh + quarantine.sh). CEEX-main README still documents
  --ref_alloc/--vfreeze, which main no longer parses.
- Cost (Barkla): CEEX ~6-7 s per 1k of --n per rank, PHOKHARA ~0.2-1 ms per event passing
  the cuts; at equal precision PHOKHARA needed ~45x less CPU (prod100k).
